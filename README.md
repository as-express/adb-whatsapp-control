# WhatsApp ADB API

HTTP-обёртка над реальным WhatsApp на Android-телефоне, подключённом по USB.
Сообщения печатает и отправляет настоящее приложение — это не WhatsApp Business API.

## Установка (один раз)

```bash
sudo apt install -y android-tools-adb
npm install
```

На телефоне: **Параметры разработчика → Отладка по USB**, подтвердить запрос на компьютер.

Клавиатура ADBKeyboard нужна для казахского/кириллицы/эмодзи — `adb shell input text` умеет только ASCII:

```bash
adb install -r ADBKeyboard.apk
adb shell ime enable com.android.adbkeyboard/.AdbIME
adb shell ime set    com.android.adbkeyboard/.AdbIME
```

## Запуск

```bash
node server.js                      # порт 3000
PORT=8080 API_TOKEN=secret node server.js
```

`API_TOKEN` включает проверку заголовка `Authorization: Bearer <токен>`.
Если он не задан, API открыт без авторизации.

## Endpoints

### `GET /health`
```json
{ "ok": true, "device": "RZCX719H8EP", "ime": "com.android.adbkeyboard/.AdbIME",
  "queue": { "pending": 0, "running": false } }
```

### `POST /send`
```json
{ "phone": "+7 778 123 45 67", "message": "Сәлем 👋\nВторая строка",
  "send": false, "app": "business" }
```
`send: false` (по умолчанию) — только напечатать в поле ввода, **не отправлять**.
`send: true` — напечатать и нажать кнопку отправки.

`app` — `whatsapp` (обычный) или `business`. Необязательное: по умолчанию берётся
приложение, которое `/setup` определил как залогиненное на этом телефоне.

Номер принимается в любом виде: `+7 778 768 95 88`, `8 778 7689588`, `77787689588`.
Нормализуется до 11 цифр; 10-значный дополняется кодом `7`.

```bash
curl -X POST localhost:3000/send -H 'Content-Type: application/json' \
  -d '{"phone":"77787689588","message":"Сәлем 👋","send":false}'
```

### `POST /bulk`
```json
{ "send": false, "items": [
  { "phone": "77787689588", "message": "текст 1" },
  { "phone": "77077356531", "message": "текст 2" }
] }
```
Обрабатывает по очереди, отвечает после всех. Ошибка по одному получателю не роняет остальных.

### `POST /setup`
Подготовка только что подключённого телефона. Идемпотентно — на уже настроенном
аппарате просто подтвердит состояние.

Что делает:
1. проверяет, что подключён ровно один телефон и на нём есть WhatsApp;
2. определяет и запоминает **родную** клавиатуру этого телефона (по серийнику, в `.state/devices.json`);
3. ставит `ADBKeyboard.apk`, если её ещё нет;
4. включает и активирует ADBKeyboard;
5. запускает обычный WhatsApp и Business по очереди и проверяет, **в какой из них
   выполнен вход** — незалогиненный открывается на экране регистрации и чат открыть
   не может. Рабочее приложение запоминается и дальше используется по умолчанию.

Шаг 5 занимает ~10 сек на каждое установленное приложение.

```bash
curl -X POST localhost:3000/setup
```

### `POST /ime`
```json
{ "mode": "native" }
```
`adb` — включить ADBKeyboard, `native` — вернуть **родную клавиатуру этого телефона**
(берётся из запомненного состояния, а не хардкодом — работает на любом вендоре).

## Смена телефона

```bash
adb devices
curl -X POST localhost:3000/setup
```

Перезапускать сервер не нужно — устройство определяется на каждом запросе.
`/setup` сам поставит клавиатуру на новый аппарат и запомнит его родную.

Чего он **не** сделает: не включит USB-отладку (только вручную на телефоне),
не подтвердит RSA-запрос авторизации, не залогинит WhatsApp.

## Коды ошибок

| code | HTTP | что значит |
|---|---|---|
| `BAD_PHONE` | 400 | номер не приводится к 11 цифрам |
| `EMPTY_MESSAGE` | 400 | пустое поле `message` |
| `UNAUTHORIZED` | 401 | неверный `Bearer`-токен |
| `BAD_APP` | 400 | `app` не `whatsapp` и не `business` |
| `APP_NOT_INSTALLED` | 503 | запрошенная версия WhatsApp не установлена |
| `APP_NOT_LOGGED_IN` | 503 | приложение стоит, но вход не выполнен |
| `NO_LOGGED_IN_APP` | 503 | `/setup`: ни один WhatsApp не залогинен |
| `NO_ADB` | 503 | adb не установлен |
| `NO_DEVICE` | 503 | телефон не подключён |
| `MULTIPLE_DEVICES` | 503 | подключено больше одного устройства |
| `WRONG_IME` | 503 | активна не ADBKeyboard |
| `CHAT_NOT_OPENED` | 504 | поле ввода не появилось за 20 сек |
| `SEND_BUTTON_NOT_FOUND` | 504 | текст напечатан, но отправить не удалось |

## Как это устроено

- Элементы UI ищутся через `uiautomator dump` по `resource-id`, а не по координатам —
  вёрстка WhatsApp и разрешение экрана могут меняться.
- Префикс `resource-id` зависит от приложения: `com.whatsapp:id/entry` против
  `com.whatsapp.w4b:id/entry`. Поэтому пакет определяется до поиска элементов,
  а ссылка направляется в него через `am start -p <пакет>` — иначе при двух
  установленных версиях систему выбирает приложение сама.
- Текст передаётся в ADBKeyboard как base64 через broadcast — поэтому проходят
  юникод, эмодзи и переносы строк.
- `adb` вызывается через `execFile` с массивом аргументов, без шелла — `&`, `?`,
  кавычки в тексте безопасны.
- Все операции идут через последовательную очередь (`lib/queue.js`): телефон один,
  параллельные запросы перебивали бы друг другу ввод.

## Ограничения

- **Один телефон = одна очередь.** Пропускная способность ~5–10 сообщений в минуту.
- Телефон должен быть разблокирован; при PIN-коде — разблокировать вручную.
- Пока активна ADBKeyboard, экранной клавиатуры нет — печатать на телефоне руками
  не получится. Возвращать через `POST /ime {"mode":"native"}`.
- WhatsApp может счесть массовую рассылку незнакомым номерам спамом и заблокировать
  аккаунт. Ограничения на стороне WhatsApp здесь не обходятся.
